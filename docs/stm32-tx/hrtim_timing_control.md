# HRTIM タイミング制御ノート（STM32G474RET6 / 6.78 MHz WPT TX）

作成: 2026-11-13。根拠資料は RM0440 Rev 9（以下 RM）、DS12288 Rev 6（DS）、AN2606 Rev 71（AN）。
数値の出典と原文は同じフォルダの `st_verification.md` にまとめてある。

表記: **［資料］** は資料に書いてあること、**［推論］** は資料から私が導いたこと（実機で確認が必要）。

---

## 0. 先に結論

1. **エッジ位置は 184 ps 刻みで置けるが、測る側（キャプチャ）は 5.9 ns 刻み**。HRTIM の高分解能は出力エッジ・周期にだけ効き、カウンタ読み出しとキャプチャには効かない（RM 28.3.3 p.890、28.3.4 p.902）。
2. **デッドタイムユニットの刻みは 737.5 ps**（tHRTIM/8、RM 28.3.4 p.911）。184 ps で詰めたいときは 4 つのコンペアで両出力を個別に作る方式になるが、ハードウェアの重なり防止が無くなる。
3. **同一周期内で ZVS を検出してゲートを動かす制御は成立しない**。同期経路は入力から出力まで 56 ns typ / 66 ns max、高速経路でも 12〜19 ns typ に LM5113 の 28 ns が加わり、半周期 73.7 ns・デッドタイム 8〜10 ns に対して遅すぎる。高速モードには「イベント後 11 fHRTIM 周期（64.9 ns）出力を変えられない」制約もある（RM 28.3.8 p.928）。適応制御は「多数周期で測定 → ソフトでレジスタ更新」の遅いループにする。
4. **1 ns 以下の測定分解能は、パターン全体を 184 ps ずつずらして 5.9 ns の量子化境界を探す等価時間（バーニア）法で得る**［推論］。絶対値は経路遅延（内蔵 COMP、分圧 RC、ドライバ）の校正が要る。
5. 初回ブリングアップはデッドタイムユニット＋ハーフモード、デッドタイム約 20 ns から。LM5113 の上下マッチングは最大 8 ns で、これは狙うデッドタイムと同じ大きさである。

## 2. 推奨 HRTIM 構成

### 2.1 クロックと DLL（RM 28.3.24 p.987、28.5.75 p.1116）

1. RCC で PLL を 24 MHz / 8 × 113 / 2 = 169.5 MHz にし、HRTIM のクロックを有効化する（上限 170 MHz、DS 表 59）。
2. `HRTIM_DLLCR.CAL = 1` を書き、`HRTIM_ISR.DLLRDY` を待つ。**DLLRDY 前にカウンタを起動しない**。
3. 続けて `CALEN = 1` と `CALRTE` を設定して周期校正にする（CAL と CALEN は同時に書かない）。CALRTE は 00 = 6.2 ms 〜 11 = 12 µs。どれが出力ジッタに有利かは資料に無いので、スコープで比べて決める。
4. `CKPSC = 0` をコンペア・周期より先に書く（RM p.890）。起動後は変更不可。イベントをやり取りするタイマ同士は同じ CKPSC にする。

### 2.2 タイマ割り当て

| 資源 | 用途 |
|---|---|
| Timer C（CHC1 = PB12、CHC2 = PB13） | レグ A |
| Timer D（CHD1 = PB14、CHD2 = PB15） | レグ B |
| Master | 可変位相が必要になったときの時間基準（2.4） |
| Timer A/B/E/F | 空き。検出用の補助タイマとして使える（4 章） |
| FLT3 = PB10、FLT4 = PB11 | Fault。FLT3 のブランキングは Timer C、FLT4 は Timer D に固定（RM 表 252 p.966） |
| EEV1 = PC12、EEV2 = PC11 | 外部コンパレータ出力（高速モード可） |
| EEV4 = COMP1（PA1）、EEV5 = COMP3（PC1） | 内蔵コンパレータ（高速モード可、RM 表 223 p.887） |

**PB14 について**: システムブートローダは PB14 を SPI2_MISO として 3.3 V に駆動する（AN 表 118 p.286）。レグ B は「PB14 → ローサイド、PB15 → ハイサイド」に入れ替えることを勧める。相補ペアはどちらの出力をどちらの FET に使ってもよいので、ファームの負担は無い。以下では出力 1 側を「基準波形側」と呼び、FET の上下は配線に合わせて読み替える。

### 2.3 相補ゲート信号の作り方

#### 方式 A: デッドタイムユニット（初回ブリングアップ用）

［資料］`HRTIM_OUTxR.DTEN = 1` にすると、出力 1 用の SET/RST で定義した基準波形から相補ペアが作られ、`SETx2R/RSTx2R` は無視される。基準の立上り後に DTR、立下り後に DTF が入る（RM p.910-911）。

設定例（180° 固定、Master 不要）:

| レジスタ | Timer C | Timer D |
|---|---|---|
| `TIMxCR` | CONT = 1、HALF = 1、PREEN = 1、TxRSTU = 1、CKPSC = 0 | 同じ |
| `PERxR` | 800（CMP1 は自動で 400、RM p.900） | 800 |
| `SETx1R` / `RSTx1R` | PER / CMP1 | CMP1 / PER（配線を入れ替えた場合は Timer C と同じ） |
| `DTxR` | DTPRSC = 0、DTR・DTF = 27（19.9 ns）から開始 | 同じ |
| `OUTxR` | DTEN = 1、POL1/2 = 0、IDLES1/2 = 0、FAULT1/2 = 10 | 同じ |

- 到達できる値: 8.11 ns（11）、8.85 ns（12）、9.59 ns（13）、10.32 ns（14）。立上り側と立下り側は独立。
- 利点: 重なりを作るには符号ビットを立てる必要があり、`DTRSLKx/DTFSLKx` で符号を次のリセットまで固定できる（RM p.913）。値まで固定する `DTRLKx/DTFLKx` は適応制御と両立しないので使わない。
- `DTxR` はプリロード対象（RM 表 244 p.943）なので、走行中に更新イベントで切り替えられる。
- 制約: 刻み 737.5 ps。`DTEN` はタイマ動作中に変更不可。
- 8〜10 ns は 3 tHRTIM（17.7 ns）より短い。RM は「735 ps まで」と書き、通常動作での下限は示していない。最初にスコープで両エッジとも確認する。

#### 方式 B: 4 コンペア（微調整用）

`DTEN = 0` とし、CHx1 を CMP1 で SET・CMP2 で RST、CHx2 を CMP3 で SET・CMP4 で RST。4 つのエッジが 184 ps 刻みになる。

- ［資料］制約は「各 CMP が 96〜PER」「同じ出力の SET と RST が 3 tHRTIM 以上離れている」（RM 28.3.7 p.922-924）。デッドタイムは別々の出力のイベント間隔なので、この狭パルス規則の対象外。
- ［推論］HRTIM 側に重なり防止が無い。LM5113 にも無いので、**レジスタ値が間違えば即貫通**。必ず (1) `hrtim_calc.py` の検査関数を通した値だけを書く、(2) `TxUDIS` で囲んでプリロード更新、(3) FLT3 の非同期 Fault を有効のまま、の 3 点を守る。
- CMP3/CMP4 を使い切るので、Fault ブランキング窓（CMP3/CMP4 を使う）と自タイマ内のイベントフィルタに使えるコンペアが残らない。

| | 方式 A | 方式 B |
|---|---|---|
| デッドタイム刻み | 737.5 ps | 184.4 ps |
| 重なりのハード保護 | 符号ロックあり | なし |
| 使うコンペア | 0〜2 本 | 4 本 |
| 周波数変更 | PER だけ（HALF） | PER と 4 つの CMP |
| 推奨 | 初回〜通常運転 | A で最適点が分かった後の詰め |

### 2.4 レグ間位相

- **180° 固定**: 2.3 の表の通り。Timer C と D は同じ PER・同じクロックなので、`HRTIM_MCR` の TCCEN と TDCEN を **1 回の書き込み**で立てれば同期したまま走る（RM 28.3.5 p.914）。
- **可変位相（方式 1、カウンタはそのまま）**: 基準波形を CMP1（SET）と CMP2（RST = CMP1 + 400）で作り、レグ B の値をずらす。どのコンペアも 0〜95 tick に置けないので、片方のレグを固定すると相対位相に届かない区間が残る（方式 A で 96 tick × 2 か所、方式 B ではレグ A を最小オフセットに固定した場合 290 tick）。両レグのオフセットを一緒に動かせば全位相に届くが、その切り替え時にブリッジ全体の絶対位相が跳ぶ［推論］。`hrtim_calc.full_bridge_compares()` がこの探索を行う。
- **可変位相（方式 2、Master でリセット）**: Master の PER = 800。Timer C を MSTCMP2（固定、例 400）、Timer D を MSTCMP1（96〜800 で可変）でカウンタリセットし（`RSTCR/RSTDR`）、同じ Master イベントで出力を SET、自タイマの CMP1（半周期）で RST する。相対位相は MSTCMP1 − 400 = −304〜+400 tick が切れ目なく使える。RM 28.4.3（p.991-992）の多相コンバータ例と同じ構成で、特徴一覧は「位相をフル分解能で調整できる」とする（p.882）。ただし Master コンペアによるリセットが 184 ps の端数を保つという明文と、その遅延値は無い。スコープで位相の刻みを確認すること。このとき従属タイマの PER は Master 周期より大きくしておく（リセットとロールオーバーが重ならないように）［推論］。

### 2.5 プリロードと更新（RM 28.3.11 p.942-946）

- プリロード対象: PER、REP、CMP1〜4、DTxR、SETx1R/RSTx1R/SETx2R/RSTx2R、RSTxR。
- 手順: `HRTIM_CR1` の TCUDIS・TDUDIS（Master も使うなら MUDIS）を 1 にする → 新しい値をすべて書く → 同じレジスタへの 1 回の書き込みで 0 に戻す → 次の更新イベント（TxRSTU = ロールオーバー、または TxREPU = 繰り返しカウンタ 0）で 2 つのタイマが同時に切り替わる。
- 更新イベントで出力を SET/RST しない（低分解能で最大 31/32 tHRTIM 遅れる、RM p.899）。
- 走行中に変えてはいけないもの: CKPSC、DTEN、POL、FAULTx（Fault 有効時）、DELCMP、EExFLTR/EExLTCH、EExSRC/POL（高速モード時）、TxCEN の連続書き換え（8 fHRTIM 周期以内）。
- 周期ごとの割り込みは使わない（6.78 MHz）。繰り返しカウンタ REP = 255 で 26.5 kHz、通常は割り込み無しでソフトの都合の良いときに上の手順を回せばよい。

### 2.6 起動・停止シーケンス（RM 28.3.24 p.987-988、28.3.14 p.952-954）

起動:

1. リセット直後、PB12〜PB15 はアナログ（Hi-Z）。外付け 47 kΩ で LM5113 入力は Low。HV は OFF（PB0 = Low）。
2. クロック、DLL 校正（2.1）。
3. カウンタ停止のまま Timer C/D を設定（2.3）。Fault 入力を設定（2.7）。
4. `OUTxR` の POL、IDLES、FAULT を確定してから、GPIO を HRTIM の AF に切り替える。この時点で出力は IDLE（非アクティブ = Low）。
5. プリロードを有効にし、ソフト更新（`CR2` の TCSWU・TDSWU）でアクティブレジスタへ転送。
6. 方式 A では、RUN に入る前にソフト強制（`RSTx1R` の bit 0 = SRT）で基準波形を確定させる（RM p.988 の注記）。RM 28.5.28 のビット説明はこのビットを SST と書いているが、レジスタマップでは SRT。ローサイドが先にオンになる向きにすれば、ブートストラップコンデンサの充電を兼ねられる［推論］。
7. `OENR` に TC1OEN・TC2OEN・TD1OEN・TD2OEN を 1 回で書く。
8. `MCR` に TCCEN・TDCEN（必要なら MCEN）を 1 回で書く。
9. ゲート波形を確認できてから HV を入れる。

停止:

1. `ODISR` に 4 出力分を 1 回で書く → IDLE（Low）。IDLE は FAULT より優先（RM p.953）。
2. HV を切る。カウンタ停止はその後でよい。
3. 非常時は Fault 入力に任せる（下記）。Fault 後は、ソフトが OEN を書き直すまで FAULT 状態のまま。

### 2.7 Fault 設定（RM 28.3.17 p.963-967、DS 表 60）

| 項目 | FLT3（PB10、高速過電流） | FLT4（PB11、外部・非常停止） |
|---|---|---|
| `FLTxSRC` | 00（ピン） | 00（ピン） |
| `FLTxP` | 基板のプルダウンに合わせるなら 1（High で Fault） | 同左 |
| `FLTxF` | 0000（非同期、ピン→出力 9 ns typ / 20 ns max） | 0010〜0011（fHRTIM × 4〜8 サンプル = 24〜47 ns）でノイズ除去 |
| ブランキング | Timer C のリセット〜CMP3、または CMP4〜CMP3（方式 A のとき） | Timer D で同様 |
| `FLTCR`・`FLTDR` | FLT3EN = 1 | FLT4EN = 1（両タイマとも両方有効） |

- **`FAULT1/2[1:0]` のリセット値 00 は「Fault を無視」**。4 出力とも 10（非アクティブ）にする。Hi-Z（11）は 47 kΩ と入力容量で落ちるのを待つことになるので使わない。
- 設定は `FLTxE = 0` の間に書く。確定後は `FLTxLCK`、`FLTLCK` でロックできる。
- 最小パルス幅 7 ns。LM5113 の遅延（28 typ / 45 max）を足すと、Fault から FET オフまで 37 ns typ / 65 ns max［推論］。
- 極性は「Low で Fault ＋プルダウン」にすると、配線が外れたときに止まる側になる［推論］。
- クロック監視（CSS）は HRTIM のシステム Fault に常時つながっている（RM 表 230 p.889）。RCC で CSS を有効にすれば、水晶停止時に出力が FAULT 状態になる。
- PB10/PB11 は TT_a（3.6 V まで）。J301 から 5 V ロジックを入れない。

### 2.8 デバッグ停止（RM 28.3.25 p.988-989、DBGMCU_APB2FZR bit 26）

- `DBG_HRTIM_STOP = 1`: コア停止でタイマが止まり、RUN 中の出力は FAULT 状態（FAULTx = 10 なら Low）になる。再開しても自動では戻らず、OEN を書き直す。開発中はこちら。
- `DBG_HRTIM_STOP = 0`: コアが止まっても HRTIM は動き続ける。ソフトの保護は効かず、ハード Fault だけが残る。
- このビットは電源投入リセットでのみクリアされる。

## 3. タイミング予算

### 3.1 出力経路（コマンド → FET）

| 要素 | typ | max | 出典・備考 |
|---|---|---|---|
| HRTIM エッジ位置 | 0.184 ns 刻み | | RM |
| PLL 周期ジッタ（RMS） | 0.021 ns | | DS 表 46（150 MHz 時の typ） |
| GPIO 立上り・立下り | | 2.5 ns（10 pF）/ 5.8 ns（50 pF） | DS 表 56、OSPEEDR = 10。11 なら 1.7 / 3.3 ns（30 pF） |
| 直列 R × 入力容量 | 0〜1 ns | | 0〜33 Ω × 約 30 pF［推論］ |
| LM5113 伝搬遅延 | 28 ns | 45 ns | 設計メモ（TI 資料） |
| LM5113 上下マッチング | 1.5 ns | **8 ns** | 同上 |

ゲートでの実効デッドタイム = 設定値 +（オン側遅延 − オフ側遅延）。個体によっては設定 8 ns が 0〜16 ns になり得る。だから (1) 20 ns から始めて縮める、(2) レグごと・エッジごとに実測して補正値を持つ、の順にする。

### 3.2 検出経路（スイッチノード → HRTIM）

| 要素 | typ | max | 出典・備考 |
|---|---|---|---|
| 分圧（15 k / 1 k、出力 938 Ω）＋配線 60 mm＋負荷 | 時定数 5〜14 ns、50 % 到達で 3〜10 ns（補償なしの場合） | | ［推論］配線 4〜8 pF（0.2 mm 幅、層間 0.1〜0.2 mm の概算）、パッド・ヘッダ 1〜2 pF、R343/R344 実装時は MCU ピン 5 pF（DS 表 54） |
| 配線 60 mm の伝搬 | 0.4 ns | | ［推論］ |
| 内蔵 COMP（100 mV オーバードライブ、出力ピンまで） | 16.7 ns | 31 ns | DS 表 79 |
| 内蔵 COMP を使うことによる増分（ピン入力との差） | 約 6〜7 ns | 8〜10 ns | DS 表 61・62 の差［推論］ |
| 外付け高速コンパレータ | 2〜5 ns 級 | | 部品未選定。仮定 |
| 再同期（キャプチャ） | 1〜2 tHRTIM = 5.9〜11.8 ns | | RM p.905 |
| キャプチャ量子化 | 5.9 ns | | RM p.890、p.902 |
| 同期経路で出力が動くまで（ピン→ピン） | 56 ns（内蔵 COMP: 62 ns） | 66 ns（76 ns） | DS 表 62。RM は 5〜6 周期（表 241）または 6〜7 周期（図 244） |
| 高速経路（ピン→ピン） | 12 ns（内蔵 COMP: 19 ns） | 23 ns（31 ns） | DS 表 61 |
| 高速モード後の出力変更禁止 | 64.9 ns | | RM p.928 |

配線 60 mm の影響:

- 分圧の後ろに 60 mm あると、配線容量が RC の主要因になり、遅延がデッドタイムと同じ桁になる。補償コンデンサ C338/C339 は 1 pF なら対地容量 15 pF のときに合い、少なければ行き過ぎ（ピーク電圧増）、多ければ鈍る。2026-11-14 に初期値を 0.5 pF（行き過ぎない側）に変えた（7.5 節）。**対地側のトリム C のフットプリント**を分圧点か J301 近くに用意し、実測で合わせる。
- 15 kΩ と 1 pF はスイッチノード直近に置く。高電圧側を 60 mm 引くと、スイッチノードに容量が付き、放射源にもなる。
- A・B の 2 本は長さと層を揃える。差は直接デッドタイム測定の差になる。
- J301 にプローブをつなぐと対地容量が倍近くになり、MCU が見る波形も変わる。測定時とそうでないときで校正値が違う点に注意。
- PA1/PC1 は正方向の注入が許されない（DS 表 15）。補償過多のときのピークが 3.6 V を超えないことを、R343/R344 を実装する前に確認する。

### 3.3 現実的に得られる分解能

| 方法 | 分解能 | 確度（絶対値） |
|---|---|---|
| キャプチャ 1 回 | 5.9 ns（＋再同期で 1 周期の不確かさ） | 経路遅延の校正前は ±10 ns 程度［推論］ |
| キャプチャの単純平均 | 改善しない（スイッチノードはタイマと同期しているので毎回同じ値になる）［推論］ | 同上 |
| バーニア掃引（4.1） | 0.2〜0.5 ns（ノイズとジッタで決まる）［推論］ | 一度スコープで校正すれば ±1 ns 程度。温度による遅延変化は不明 |

## 4. 適応デッドタイム / ZVS 制御の選択肢

共通の前提: 周期ごとの割り込みは不可。ハードで条件判定や保持を行い、ソフトは kHz 程度で結果を読み、プリロード経由で DT やコンペアを更新する。

### 4.1 キャプチャ＋バーニア掃引（推奨の第一候補）

- 使う機能: EEV（外部コンパレータ: EEV1/2、内蔵: EEV4/5）、Timer C/D のキャプチャ（`CPT1xCR` の EXEVnCPT）、プリロード。
- 仕組み［推論］: 出力エッジは fHRTIM クロックに対して 1/32 周期刻みで動かせるが、外部イベントは fHRTIM クロックで取り込まれる。そこで**全エッジのコンペア値を k = 0〜31 tick 一斉にずらす**と、スイッチノードの遷移も k × 184 ps ずれ、ある k でキャプチャ値が 1 LSB（32 tick）変わる。その k が遷移時刻の端数になる。各 k で数回読んで多数決を取ればジッタ分布も分かる。
- 構成上の条件: タイマはフリーランで、エッジは明示的なコンペア（CMP1 = a + k、CMP2 = a + 400 + k、a ≥ 96）で作る。HALF モード（PER と CMP1 に固定）のままではずらせない。1 回の掃引は更新 32 回で、1 kHz 更新なら 32 ms。
- RM の裏付け: キャプチャが fHRTIM 分解能であること、エッジ位置が 1/32 刻みであること、キャプチャ要因に EEV1〜10 が選べることは明記。掃引法そのものは RM に無い。
- 落とし穴: 上書き防止は無い（常に最新周期の値）。エッジ感度は `EExSNS` で選ぶが、キャプチャに使う外部イベントは設定によらずエッジ動作（RM p.926）。カウンタ停止中はイベントが捨てられる。

### 4.2 しきい値掃引による等価時間サンプリング（内蔵 COMP ＋ DAC3）

- 使う機能: COMP1/COMP3（INM = DAC3_CH1、RM 表 200）、EEV4/EEV5、4.1 の時刻測定。
- 仕組み［推論］: DAC3 のしきい値を段階的に変え、各しきい値での交差時刻を 4.1 で求めると、スイッチノードの立上り・立下り波形 V(t) を再構成できる。ZVS が不完全なら、ゲートが入る時刻に段差として現れる。
- 分解能: 時間は 4.1 と同じ。電圧は DAC 12 bit だが、COMP オフセット −9〜+3 mV（1/16 分圧でスイッチノード換算 −144〜+48 mV）とノイズが支配的。
- 落とし穴: DAC3 は COMP1 と COMP3 で共用（別々にするには片方を DAC1_CH1）。169.5 MHz では `HFSEL = 10` が必要（RM 表 191）。COMP の遅延はオーバードライブに依存するので、しきい値によって時刻がずれる（資料の値は 1 条件のみ）。COMP の帯域より速いリンギングは見えない。入力範囲は 0〜VDDA なので、GaN の逆導通（負電圧）は見えない。COMP 自体のブランキング源に HRTIM は無い（RM 表 201）。

### 4.3 窓・ブランキング＋イベントカウンタによる早い/遅い判定

- 使う機能: タイマごとのイベントフィルタ（`EEFxR1/2`）とイベントカウンタ（`EEFxR3`）、出力の SET/RST フラグ。
- 仕組み: 「カウンタリセットから CMPx まで」をブランキングにすれば、**CMPx より後に来たイベントだけ**が通る。窓モードで `EExLTCH = 1` にすれば、**CMP2/CMP3 より前に来たイベントだけ**が窓の終わりに出る。イベントカウンタを累積モード（EEVxRSTM = 1）にすると、N 周期連続で通ったときだけ下流へ伝わる（N = 1〜64）。伝わったイベントで空きタイマの出力を SET し、そのフラグをソフトが読んで DT を 1 刻み動かす。
- RM の裏付け: フィルタ、ラッチ、カウンタの動作は明記（28.3.9 p.929-935）。
- 落とし穴:
  - カウント値は読めない。タイマ 1 つにカウンタ 1 つ。エッジ感度のイベント専用。
  - 窓モードで `EExLTCH = 0` だと、イベントが来なくても窓の終わりにタイムアウトイベントが出る。判定には必ずラッチ付きかブランキングを使う。
  - フィルタの種類は走行中に変えられない（境界の CMP 値は変えられる）。
  - 境界が外部イベントに対して 184 ps で効くのか 5.9 ns で効くのかは資料に無い。5.9 ns だとしても 4.1 と同じ掃引で端数を出せる［推論］。
  - キャプチャやカウンタリセットがフィルタ後のイベントを見るのかどうかも明記が無い（ADC トリガはフィルタ前と明記、RM p.973）。出力の SET/RST で観測するのが確実。
  - 方式 B では自タイマのコンペアが余らないので、Timer A などの空きタイマを同じ周期で走らせて判定に使う。Timer C なら TD2、Timer D なら TC2 の波形をブランキング源にもできる（RM 表 242）。

### 4.4 高速モードのイベントで出力を直接動かす

- 使う機能: `EExFAST = 1`（EEV1〜5）、クロスバーの EXTEVNT。
- 資料上は可能。ただし (1) レベル感度のみ、(2) トグル不可、(3) イベント後 64.9 ns は出力を変えられない、(4) 最短でもコンパレータ込み 19 ns typ ＋ LM5113 28 ns。
- この基板では**ゲート出力には使わない**。半周期 73.7 ns のうち 64.9 ns がロックされ、次の正規エッジと衝突する。ZVS 到達を待ってオンする用途には遅すぎる。保護は Fault 入力のほうが速くて制約も少ない。

### 4.5 資料の外にある遅いループ［推論］

- 入力電流最小化: PAC1720 の入力電流が最小になる DT を山登りで探す。校正不要だが、負荷変動と区別しにくい。
- 逆導通時間の検出: 外部回路でスイッチノードの負電圧（逆導通）を検出して積分し、ADC2_IN8（PC2）で読む。パルス自体は EEV の最小幅 7 ns より短くなり得るので、デジタル入力ではなくアナログ積分にする。

## 6. 資料が答えていない点

1. DLL がロックする fHRTIM の下限、周期校正（CALRTE）が出力ジッタに与える影響。
2. fPWM = fHRCK / PER の明示（表からの読み取り）。
3. Master や他タイマのコンペアによるカウンタリセットが 184 ps の端数を保つか、その遅延。
4. 8〜10 ns（3 tHRTIM 未満）のデッドタイムでの挙動。「735 ps まで」とあるだけ。
5. キャプチャ・カウンタリセットがフィルタ前後どちらのイベントを見るか。ブランキング・窓の境界の時間刻み。
6. 同期経路の遅延の不一致（5〜6 周期、6〜7 周期、56/66 ns）。
7. 禁止範囲（1〜95）のコンペア値を書いたときの挙動。
8. `ODISR` による停止の遅延、非同期かどうか。
9. 内蔵 COMP の遅延のオーバードライブ依存、COMP1 と COMP3 の差（typ は全コンパレータの平均）。
10. ブートローダがインターフェース検出後に未使用ピンを解放するか、PB13 のプル設定。
11. PLL ジッタの入力周波数依存（3 MHz 比較での値）。
12. ST 資料の範囲外: LM5113 のマッチングの温度変化、EPC2007C のスイッチング時間、FA-128 の ESR、外付けコンパレータの選定。

## 7. ZVS 検出の見通し（EPC9065 を基準に考える）

追記: 2026-11-14。根拠は EPC9065 Quick Start Guide rev 2.0（以下 QSG）と EPC2007C データシート（2021 年 4 月版）。この基板の電力段は EPC9065 と同じ構成（EPC2007C × 4、LM5113、同期ブートストラップ、非共振の ZVS タンク）なので、まず元の評価ボードが ZVS をどう扱っているかを確認し、そのうえで検出回路の役割を決める。

### 7.1 EPC9065 自体のやり方［資料］

- ZVS は**タンクのインダクタ電流だけ**で作る。L_ZVS と直列の C_ZVS（1 µF、直流阻止）は共振させない。インダクタには三角波電流が流れ、ピークは VPP / (8 f L_ZVS)。
- スイッチノードの遷移時間は QSG の式で決まる: **Δt_vt = 8 · f · L_ZVS ·（2 · C_OSSQ + C_well）**。C_OSSQ は電荷等価の出力容量、C_well はゲートドライバの寄生容量（LM5113 で 20 pF）。VPP は式に直接は入らず、C_OSSQ の電圧依存を通じてだけ効く。
- デッドタイムは**無負荷で**ポテンショメータ（P71〜P74）を回し、スコープで合わせる（VAMP 5 V で波形を確認してから使用電圧へ上げる）。遷移時間は「典型的に 2〜12 ns」。
- 負荷インピーダンスの変動に対する余裕は、**L_ZVS を小さくしてターンオフ時の電流を増やす**ことで得る、と書いてある（そのぶん素子損失は増える）。評価ボードの定格は VAMP 0〜80 V、出力 1.8 A RMS（各レグ）。
- **制御器も保護も無い**。負荷が変わって ZVS が崩れても、評価ボードは何もしない。

### 7.2 この基板の数値［推論］

L301 = L302 = 390 nH、f = 6.78 MHz から 8 f L = 21.15 Ω。C_OSSQ はデータシートの C_OSS–V_DS 曲線（0 V で約 270 pF、10 V 215 pF、20 V 170 pF、30 V 140 pF、50 V 110 pF）を積分して求めた。

| VPP | C_OSSQ | タンク電流ピーク VPP / 21.15 Ω | 無負荷の遷移時間 | 完全ハードスイッチング時の損失（1 レグ） | R339 / R341（15 kΩ）の損失 |
|---|---|---|---|---|---|
| 5 V | 258 pF | 0.24 A | 11.3 ns | 0.1 W | 1 mW |
| 12 V | 240 pF | 0.57 A | 10.6 ns | 0.5 W | 4 mW |
| 24 V | 209 pF | 1.13 A | 9.3 ns | 1.7 W | 17 mW |
| 36 V | 186 pF | 1.70 A | 8.3 ns | 3.4 W | 38 mW |
| 50 V | 167 pF | 2.36 A | 7.5 ns | 6.0 W | 73 mW |

- ハードスイッチング損失は 2 f ·（VPP · Q_OSS + ½ C_well VPP²）。1 回の遷移でバスから Q_OSS を引き、その VPP · Q_OSS が 2 個の FET で熱になる。
- 15 kΩ は 0402（定格 62.5 mW、素子最高電圧 50 V）なので、**分圧回路が使えるのは VPP 45 V 程度まで**。それ以上で使うなら 0603 に替える。
- 無負荷の遷移時間は 7.5〜11.3 ns で、3.1 節の「20 ns から始めて縮める」の到達点はこのあたりになる。

### 7.3 負荷でどれだけ動くか［推論］

遷移に使える電流は、タンク電流のピークに**切り替えの瞬間の負荷電流**が足し引きされたものになる。差動出力の基本波振幅は 4 VPP / π、負荷電流を I_o sin(ωt − φ) とすると（φ > 0 が誘導性）、切り替え時の電流は VPP / (8 f L) + I_o sin φ。

VPP = 24 V、負荷 47 Ω（I_o = 0.65 A）の例:

| 負荷の位相 φ | 切り替え時の電流 | 遷移時間 |
|---|---|---|
| +30°（誘導性） | 1.46 A | 7.2 ns |
| 0°（純抵抗） | 1.13 A | 9.3 ns |
| −30°（容量性） | 0.81 A | 13.0 ns |
| −60° | 0.57 A | 18.4 ns |

- 無負荷で合わせた固定デッドタイムは、負荷の位相が振れると 2 倍前後ずれる。**負荷位相が支配的**で、VPP や素子ばらつきの影響より大きい。
- I_o |sin φ| がタンク電流のピークを超える容量性負荷では、どれだけ待ってもスイッチノードは反対側のレールに届かない（ZVS 不成立）。24 V では I_o が 1.13 A を超える重い負荷（約 27 Ω 以下）で容量性に大きく振れた場合に起こる。受電コイルが離れて反射インピーダンスが変わる WPT では現実にあり得る条件である。

### 7.4 ずれたときの代償［推論］

| 状況 | 1 レグあたりの損失の目安（24 V） |
|---|---|
| デッドタイムが短く、電圧が 20 % 残った状態でオン | 0.07 W |
| 同 30 % | 0.15 W |
| 同 50 % | 0.43 W |
| デッドタイムが長く、逆導通（V_SD 約 2.3 V、1.1 A）が続く | 1 ns あたり 0.035 W |
| ZVS 不成立（完全ハードスイッチング） | 1.7 W（36 V では 3.4 W） |

- 数 ns のずれは 0.1〜0.2 W で、最適点は浅い。**効率を詰める目的だけなら検出回路の効果は小さい**。
- 効くのは最後の行で、EPC2007C（1.7 × 1.1 mm の LGA）に 1.7〜3.4 W が乗り続ける状態を**検出して止める・VPP を下げる**ことに価値がある。EPC9065 にはこの機能が無い。

### 7.5 検出回路にできること・できないこと

できること［推論］:

- **遅いループでのデッドタイム自動調整**（4.1〜4.3）。多数周期をかけて遷移時刻を 0.2〜0.5 ns の分解能で測り、ソフトがデッドタイムを更新する。内蔵 COMP の遅延 16.7 ns typ は固定オフセットとして校正で消える。絶対値ではなく、デッドタイムを縮めていって遷移の形が変わり始める点（折れ点）を探す使い方なら、校正の誤差に強い。
- **ZVS 喪失の監視**。ゲートをオンする時刻にスイッチノードがしきい値を越えていない周期が続いたら（4.3 のイベントカウンタ）、VPP を下げるか出力を止める。
- 負荷位相の変化の観測（遷移時間そのものが位相の指標になる）。

できないこと［資料・3 章］:

- **同一周期内の制御**。検出から出力まで 56 ns typ（同期経路）＋ LM5113 28 ns で、半周期 73.7 ns に収まらない。
- 逆導通（負電圧）の検出。COMP の入力範囲は 0〜VDDA。
- COMP の帯域（遅延 16.7 ns）より速いリンギングの観測。

2026-11-14 の変更（第 3 版の基板）:

- **R343 / R344 を 100 Ω で実装**（HRTIM バリアント）。これが無いと PA1 / PC1 は分圧点につながらず、内蔵 COMP は何も見ない。100 Ω とピン容量 5 pF で 0.5 ns の遅れ、行き過ぎ時の注入電流の制限を兼ねる。
- **C338 / C339 を 0.5 pF（±0.1 pF）で実装**（同上、以前は 1 pF・未実装）。コンパレータをつないだ状態の分圧点の対地容量は 12〜14 pF（MCU ピン 5 pF、配線 40〜60 mm、ヘッダ）で、ちょうど補償するには抵抗の浮遊容量込みで 0.8〜0.9 pF が要る。
  - 0.5 pF ＋浮遊容量では、段差の 55〜75 % が即座に現れ、残りが時定数 約 12 ns で追いつく（補償不足）。**行き過ぎは起きない。**
  - 1 pF（±0.25 pF）は公称で 2 割前後、最悪 7 割の行き過ぎになる。VPP 36 V で分圧点が 3.8 V に達し、PA1 / PC1 の上限 3.6 V を超える。これが 1 pF をやめた理由。
  - 補償不足の「尾」は、レールへの到達が遅れているように見える（ZVS が不完全な波形と紛らわしい）。**遷移の終わりを測る前に、実機で 0.5〜1 pF の間で合わせる**（5 章の手順 12。J301 の波形がスイッチノードの波形と重なり、行き過ぎが出ない最大値）。
- J301 の 1 番・3 番ピンは同じ分圧点なので、**内蔵 COMP を使っている間はここに長いケーブルをつながない**。10:1 プローブ（10〜15 pF）は対地容量を倍にするので、測定中は校正値が変わる。

### 7.6 検出方式が根本的に外れていた場合

基板は **EPC9065 と同じ「固定デッドタイムのアンプ」として動く**。違いはデッドタイムをポテンショメータではなく HRTIM のレジスタで決める点だけで、無負荷でスコープを見ながら合わせる手順（5 章の 9〜11）は EPC9065 と同じである。

- スイッチノードに余分に付くのは 15 kΩ と 1 pF（直列に見て約 1 pF、C_OSS の 0.5 % 以下）だけ。損失は 7.2 節の表のとおり。
- 切り離したいときは R343 / R344 を外せば MCU 側が、R339 / R341 と C338 / C339 を外せば分圧回路ごと無くなる。
- Legacy バリアント（Si5351 ＋ RC 遅延）の部品も基板上に残してあるので、HRTIM 駆動そのものに問題が出た場合の退路もある。

### 7.7 アナログ部を引き直すなら検出部はどこに置くか

**分圧点の直近に高速コンパレータを置き、MCU へはデジタル信号（EEV 入力）で送る**のが本来の形になる。

- 理由: 今の配置は 938 Ω の分圧点から MCU まで 45〜60 mm をアナログのまま引いており、配線容量が帯域と遅延を決めている（3.2 節）。コンパレータを分圧の隣に置けば、分圧点の容量は数 pF に減り、補償コンデンサの合わせ込みが要らなくなる。遅延も内蔵 COMP の 16.7 ns から 2〜5 ns 級になる。
- それでも今回の基板を今の形のまま出す理由: (1) 使い方が遅いループなので、固定の遅延は校正で消える。(2) しきい値を DAC3 で振れる内蔵 COMP は、4.2 の波形再構成に向いている。(3) 外付けコンパレータを試したくなったら、**J301 に小基板を挿せば配線済みの経路で試せる**（1・3 番 = 分圧点、5・6 番 = EEV1 / EEV2 への入力、9・10 番 = +3V3 / GND）。基板を作り直さずに比較できる。
- 引き直す場合に変える点: コンパレータ（電源 3.3 V、伝搬遅延 3 ns 級、しきい値は DAC 出力か抵抗分圧）を各レグの分圧抵抗の隣に置く。出力は EEV1 / EEV2 へ 33〜100 Ω の直列抵抗を入れて送る。分圧点からのアナログ線は J301 のモニタ用だけにする。

### 7.8 進め方

1. EPC9065 と同じ状態を先に作る: 固定デッドタイム、無負荷、VPP 5 → 12 → 24 V（5 章の 9〜11、15）。この時点で検出回路は使わない。
2. 検出経路の確認: J301 と直接プローブの比較、補償の合わせ込み、PA1 / PC1 のピークが 3.3 V 未満であること（5 章の 12）。
3. 測定だけ動かす: バーニア掃引で遷移時刻を読み、スコープの値と突き合わせる（5 章の 13、14）。デッドタイムはまだ手動。
4. 監視を入れる: ZVS 喪失が N 周期続いたら出力停止。しきい値と N は、わざと容量性の負荷にして決める。
5. 最後に自動調整を閉じる。上下限と変化率を制限する（5 章の 16）。
